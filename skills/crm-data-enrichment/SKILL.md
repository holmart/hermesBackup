---\nname: crm-data-enrichment\ndescription: Enrich SIF Agent CRM data with representative legal information from public sources\nversion: 1.0.0\nauthor: Hermes Agent\ncategory: data-enrichment\n---\n# CRM Data Enrichment Skill\n\nThis skill enriches the `sifagent-crm-clients` DynamoDB table with verified representative legal information by scraping company websites and falling back to public business registries when necessary.\n\n## When to Use\n\n- When the CRM contains missing, empty, or generic values in the `RepresentanteLegal` field\n- When you need to improve data quality for compliance, facturación, or operational purposes\n- As a periodic data quality improvement job\n\n## Prerequisites\n\n1. AWS CLI configured with permissions to read/write to `sifagent-crm-clients` table\n2. Basic web scraping tools available (curl, grep, regex)\n3. Target companies must have accessible websites with representative legal information\n\n## Skill Workflow\n\n### 1. Identify Target Records\nScans the DynamoDB table for records where `RepresentanteLegal` is:\n- Missing/not set\n- Empty string\n- \"Por determinar\"\n- \"N/A\"\n- Generic roles like \"Contacto\", \"Gerencia\", \"Servicio al Cliente\", \"Comercial\", \"Ventas\"\n\n### 2. Prioritize by Data Quality\nFocuses first on records that have:\n- Valid website URL (non-empty, accessible)\n- NIT with proper format (9+ digits)\n- Higher likelihood of finding representative legal info online\n\n### 3. Website-Based Extraction\nFor each prioritized record:\n1. Fetch the company website\n2. Look for common indicators of representative legal information:\n   - Text containing \"Representante Legal\"\n   - Text containing \"Gerente General\", \"Director\", \"Presidente\"\n   - Leadership/equipo pages\n   - \"Quienes somos\", \"About us\", \"Nosotros\" sections\n   - Legal notices, terms and conditions\n   - Contact pages with responsible person names\n3. Extract person name using pattern matching\n\n### 4. Validation & Update\nBefore updating DynamoDB:\n- Validate extracted name looks like a person's name (contains first and last name)\n- Cross-check with email patterns when possible (e.g., nombre.apellido@empresa.com)\n- Record source and timestamp for auditability\n- Perform conditional update only if new information is more specific than existing\n\n## Environment Variables\n- `AWS_DEFAULT_REGION`: AWS region (default: us-east-1)\n- `DRY_RUN`: Set to \"true\" to preview changes without updating (default: false)\n\n## Usage\n\n### As a standalone script:\n```bash\n# Preview changes first\nDRY_RUN=true hermes run skill crm-data-enrichment\n\n# Apply changes\nDRY_RUN=false hermes run skill crm-data-enrichment\n```\n\n### As a cron job (weekly enrichment):\n```bash\nhermes cronjob create \\\n  --name \"weekly-crm-enrichment\"\n  --schedule \"0 2 * * 0\"  # Sundays at 2 AM\n  --prompt \"Run CRM data enrichment for representative legal information\"\n  --skills crm-data-enrichment\n```\n\n## Output Format\n\nThe skill returns a JSON summary with:\n- `total_processed`: Number of records evaluated\n- `updated`: Number of records successfully updated\n- `skipped`: Records skipped due to missing website or invalid NIT\n- `failed`: Records where extraction failed\n- `details`: Array of per-record results\n\n## Example Output\n\n```json\n{\n  \"total_processed\": 25,\n  \"updated\": 18,\n  \"skipped\": 4,\n  \"failed\": 3,\n  \"details\": [\n    {\n      \"pk\": \"FUMIGACIONES 7 24 SAS\",\n      \"nit\": \"9009554608\",\n      \"action\": \"updated\",\n      \"old_value\": \"\",\n      \"new_value\": \"Fredy Yobanny Olarte Ramírez\",\n      \"source\": \"website\",\n      \"timestamp\": \"2026-08-07T10:30:00Z\"\n    }\n  ]\n}\n```\n\n## Limitations & Notes\n\n- Relies on information being publicly available on company websites\n- May not work for companies that don't publish representative legal info online\n- For difficult cases, consider integrating with RUES or Cámara de Comercio APIs\n- Always review a sample of changes before enabling DRY_RUN=false\n- Updates are conditional and idempotent - safe to run multiple times\n\n## Troubleshooting\n\n- If no updates occur: Check that target records actually have websites and valid NITs\n- If updates seem incorrect: Review the `details` field to see what was extracted\n- For persistent failures: Consider manual research for high-value clients\n\n## Source\n\nThis skill uses only publicly available information from company websites. No private or paid data sources are accessed.\n---\n
